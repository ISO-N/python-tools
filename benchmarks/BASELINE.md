## 统一基准

命令：

```bash
uv run python benchmarks/bench_all.py          # 3 次中位数
uv run python benchmarks/bench_all.py --quick  # 1 次，快速冒烟
```

| 指标 | 耗时 | 对比 |
|---|---:|---|
| `pdf_font_fontfile`（20 页逐页 `fontfile=`） | 14.172s | 基线 |
| `pdf_font_fontbuffer`（20 页复用 `fontbuffer=`） | 0.708s | **20.0×**，省 13.46s |
| `pdf_stamps_per_stamp`（6 页 × 20 stamp，逐个绘制） | 0.082s | 基线 |
| `pdf_stamps_one_shape`（每页单 Shape 一次 commit） | 0.052s | **1.59×** |
| `image_payload_serial`（12 张 1600×1200 JPEG） | 0.000414s | 原字节直嵌复用路径 |
| `image_payload_parallel`（同数据，4 线程） | 0.003758s | 线程池开销大于收益，见说明 |
| `pdf_to_images_serial`（24 页 1200×1600pt @100DPI PNG） | 0.841s | 基线 |
| `pdf_to_images_parallel`（同上，4 进程 spawn） | 0.443s | **1.90×** |

说明：

- `image_payload_*` 使用纯色合成 JPEG，压缩率极高且命中“原字节直嵌”路径，
  单张处理仅约 34µs；此时线程池固定开销占主导，并行反而更慢。这不是
  图片编码密集场景的代表值，实际 `images_to_pdf` 的收益主要来自跳过解码/
  重编码，而不是并行。
- `pdf_to_images` 的进程池有 64 MiB 总像素阈值与“总页数 ≤4 回退串行”设计，
  小文档不会承担 spawn 开销。基准特意使用大页面与 24 页，确保走并行路径。

## 已知限制

- 进程池使用 `spawn`：小任务（约 64 MiB 以下像素数据）直接回退串行，避免启动
  开销造成负优化。
- 图片拼图受内存带宽限制，并行收益有限；画布超过 5000 万像素时强制单线程。
- `images_to_pdf` 的插入阶段必须单线程持有 PyMuPDF `Document`，并行只覆盖
  读取/方向校正/编码预取。
- 取消无法打断单张图片正在进行的 PIL 解码，取消延迟上界约为一张图片的处理时间。
- 当前进程池验证环境为 WSL2；Windows 原生 spawn 行为一致（显式使用 spawn），
  但尚未在 Windows 实机跑基准。
